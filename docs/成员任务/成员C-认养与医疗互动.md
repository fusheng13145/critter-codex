# 成员 C · 认养、医疗与互动

> 本文只写 C 一个人要交付的东西，从《功能模块拆解与开发分工说明书》《功能分析说明书》《接口设计说明书》中抽出。分两部分：**基础模块**做完，三人合起来就能跑通一条完整演示链路；**后续模块**是基础达标之后再去加的体验项与社区功能。

## 口径说明

- **基础模块**：一期、二期里能形成完整正向闭环的部分——认养从申请到生效、就诊记录、消息中心，外加学生捐赠登记这一条跨模块协作接口。完成判据是"一条链路在页面上有完整痕迹，每一步都能指出来讲"。
- **后续模块**：三期功能与社区增强，不影响主链路演示。
- C 负责 D3 域全部 **35 个接口**：基础 14 个、后续 21 个。另外代写 B 域的 `POST /donations` 一个接口（表单组件复用），该接口由 B 验收，不计入这 35 个。
- **C 的模块刻意按"好写、好讲"选过**：全部是"提交—审核—状态推进—通知"，没有余额行锁、没有双人复核、没有并发抢单。唯一的技术点"同一只动物只能有一条生效关系"用数据库唯一索引兜底。

# 第一部分 · 基础模块（做完即可拿得出手）

## 1.1 基础范围与目标

| 覆盖模块 | 功能点 | 前端页面 | 主责数据表 |
|---|---|---|---|
| M03 认养（核心） | FR-C-02 申请、FR-C-03 审核、FR-C-04 关系与到期、FR-C-05 缴费入账 | P03 认养申请、我的认养、认养审核 | adoption_plan、adoption、adoption_payment |

## 1.3 基础模块的硬规则

| 规则 | 落地位置 | 验收方式 |
|---|---|---|
| 同一动物只能有一条生效认养 | 数据库唯一索引 `uk_adoption_active` + 提交与审核各一次校验 | 两人并发申请同一只，仅一单成功 |
| 每人同时生效认养 ≤2 | 服务层计数（事务内） | 第三单返回 30405 |
| 未入账不得生效 | 状态机：只有入账动作能把单转 ACTIVE | 跳过缴费调审核，状态不会生效 |
| 动物状态不可认养时拒绝 | 调用 B 的 `GET /animals/{code}` 判断 | 已离世动物申请返回 30406 |
| 关联动物必须是个体 | 群体编号传进来返回 30501 | 用 GRP 编号申请被拒 |
| 缴费金额不符 | 与方案金额比对，允许填 note 强制入账并标红日志 | 少缴 10 元返回 30408 |
| 入账副作用同事务 | 写缴费、改认养单、改动物标记、写日志、投递消息 | 中途失败则全部回滚 |
| 联系方式字段级权限 | 序列化层脱敏 | 公开页与游客接口都看不到 |
| 登记 ≠ 入账（捐赠） | 两态分离，公开进度只认已入账 | 学生登记后进度不变 |

## 1.4 基础完成后的演示方式

1. 学生点开一只可认养的猫 → 选方案 → 勾选承诺 → 提交申请。
2. 管理员审核通过 → 学生上传转账凭证 → 管理员确认入账。
3. 刷新动物档案：出现"已认养"标记；消息中心出现审批通过与入账成功两条未读。
4. 再让另一个学生对同一只猫提交申请 → 看到 30404 拒绝提示（这条最能体现规则）。
5. 登记一次就诊记录，在档案详情里反查得到；学生端登记一笔捐赠，公开进度仍为 0，等 B 核对后才变。

## 1.5 基础验收清单

- [ ] 认养申请→审核→缴费→生效四态在页面上都能看到。
- [ ] 已认养动物再次申请被拒，超两只被拒，群体编号被拒。
- [ ] 未入账时认养单不生效、动物未标记已认养。
- [ ] 入账后消息中心收到通知，动物档案状态同步。
- [ ] 就诊记录可从档案详情反查。
- [ ] 捐赠登记与入账在公开进度上分列显示。

## C 的模块容易讲的三个原因

1. **没有并发与事务难点**：唯一性由数据库索引兜底，"为什么不会重复"一句话就能答。
2. **每一步都有界面痕迹**：申请单号、审核状态、凭证、动物标记、消息提醒，评审能跟着页面点出来看。
3. **技术点少且集中**：只需讲清"状态机推进"和"跨模块只读接口"两件事，不会被追问锁、幂等、对账口径。

## 后续模块的实现提醒

- TNR 五节点必须复用 B 的状态机引擎，C 只配迁移表，不自己写 `if-else`。
- 到期定时任务用 A 提供的骨架，只填"到期前 7 日提醒、过期转 EXPIRED 并释放动物"两条规则，任务必须幂等可重跑。
- 留言回复的"仅本人可见"要在序列化层过滤，不能只靠前端隐藏。
- 志愿任务满额后自动关闭报名，重复报名返回明确错误。

## 与其他两人的接口边界

| 对象 | C 提供 | C 消费 |
|---|---|---|
| A | 认养状态、消息中心入口、就诊摘要 | 登录令牌与角色判断、附件上传、定时任务骨架 |
| B | 认养状态查询、捐赠登记接口 | 动物状态与状态流转、项目进度与余额、消息通道 |

C 不直接改 `animal`、`project`、`donation` 的入账字段；`POST /donations` 只新增待核对记录，入账由 B 完成。
