## 2 B 的协作边界

| 对象 | A（D1／前端） | C（D3） |
|---|---|---|
| B 提供 | `GET /animals`、`GET /animals/{code}`、`GET /groups`、`GET /points`、`GET /species` 等公开读接口；`v_*` 统计视图与口径 | 建档、状态迁移、工单流转、资金入账；`GET /animals/{code}` 供认养校验读 |
| B 依赖 | 令牌与角色判断、字典读取、`fileId` 上传、操作日志切面、脱敏序列化 | `POST /donations` 代写；认养关系写 `adoption` 后触发动物状态迁移 |
| 禁止 | B 不改 `sys_*` 表与统计口径分子分母 | B 不直接改 `adoption`、`visit`、`tnr_task`；C 不改 `animal`、`project`、`donation` |

## 3 交接与验收时点

1. `POST /donations`：C 提交 DTO 与前端字段给 B 审，B 确认金额单位（分）、凭证 `fileId`、项目归属后 C 才合并；联调前 B 跑一次入账回归。
2. `GET /animals/{code}/qrcode`：A 先落页面路由，B 保证公开字段不含领养人信息与联系方式。
3. 统计口径：A 只用 B 建的 `v_animal_overview`／`v_group_overview`／`v_project_fund`，需要新口径先提给 B 加视图，不在前端算。
4. 状态机：C 的认养审核通过后只调 `PUT /animals/{code}/status`，不直接写 `animal.status`。

## 4 仍需确认

- `GET /donations/{no}/certificate` 的 PDF 模板归属：现按 B 出数、C 渲染记；若 C 直接实现该端点，B 的 52 个要减 1、C 加 1。
- `GET /stats/fund` 现记 A（M09），但它读的是 B 的资金台账；若改为 B 实现，A 的 31 个减 1、B 加 1。
- `/visits`、`/tnr`、`/clinics`、`/tasks` 在 6.2 分组但归 C，检索时不要按章节误判。
