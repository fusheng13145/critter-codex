# T1.5 群体、目击与基础数据实现说明

> 覆盖 `03 §6.2 #11—#25` 的 P0 部分：群体建档/列表/详情/编辑、目击登记与列表、物种与点位只读、出现记录登记与列表。归并、拆分、归属修正、物种/点位写接口为 P1。

## 1 已实现接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/groups` | 群体建档，服务端发号 `GRP-年份-流水` |
| GET | `/api/v1/groups` | keyword / speciesId / status / pointId 组合筛选，分页 |
| GET | `/api/v1/groups/{code}` | 群体详情，带物种、点位名、规模区间 |
| PUT | `/api/v1/groups/{code}` | 编辑识别特征、点位集合、规模区间与计数依据 |

## 2 群体口径

- 编号：`GRP-2026-001`，走 `seq_no` 的 `GROUP` 维度独立发号，与动物编号互不影响。
- 规模：请求字段 `minSize` / `maxSize`，闭区间；`minSize >= 1` 且 `maxSize >= minSize`，否则 **30504**。
- 计数依据 `sizeBasis` 必填，避免把目测数字当事实；前端只展示区间，不展示中位数。
- 点位集合 `pointIds` 至少一个，去重后逐个校验存在，缺失返回 **30410**；写入 MySQL JSON 列。
- 识别特征必填、≤255 字；计数依据 ≤64 字。
- 建档默认 `ACTIVE`；状态迁移仍由状态机表决定，本迭代不开放改状态接口。

## 3 目击口径

- 目击必须挂靠已有群体（`POST` 路径带群体编号），落库 `assign_status = ASSIGNED`。
- 点位必须存在，时间必填，数量可空但必须为正整数，行为 ≤64 字。
- 落库后仅当 `seenAt` 晚于 `last_seen_at` 才刷新最近目击时间；旧目击补录不回退。
- 状态从 `GONE` / `UNCONFIRMED` 回 `ACTIVE` 属管理员确认动作，本迭代不自动迁移，避免系统替管理员做判断。

## 4 出现记录与基础数据

- 数量只接受 `FEW` / `SMALL_HERD` / `LARGE_HERD`；请求体用 `Object` 接收，数字直接 **30303**，不落具体只数（BR-13）。
- 照片至少一张；物种、点位必须存在；生境 ≤32 字。
- 季节筛选：春 3—5、夏 6—8、秋 9—11、冬 12/1/2，服务层下推 `MONTH(occurred_at) IN (...)`，不新增数据库字段。
- 物种、点位一期只读；点位只返回 `enabled = true`，避免前端展示已停用点位。

| 层 | 文件 |
|---|---|
| Controller | `controller/archive/GroupController.java`、`BiodiversityController.java` + 4 个请求 record |
