# T2.4 项目发起与审核上架说明

> 状态：已完成（2026-11-21）。本轮无新增数据库迁移，最新 main 为 V1→V12；项目与预算表来自 V1，捐赠只读查询只访问既有 `donation` 表。

## 1 交付范围

T2.4 对应 FR-F-01、FR-F-02、FR-F-05，覆盖：

| 能力 | 落地 |
|---|---|
| 项目发起 | `POST /api/v1/projects` 创建项目与预算明细 |
| 预算校验 | 预算合计 <= 目标金额；超出返回 `40101`，带 `targetAmount / budgetTotal / excessAmount` |
| 提交审核 | 创建/修改请求带 `submit=true`，同一事务内 `DRAFT/REJECTED -> PENDING_AUDIT` |
| 审核上架 | `PUT /api/v1/projects/{projectNo}/audit`，通过转 `FUNDING`，驳回转 `REJECTED` |
| 公开进度 | `GET /api/v1/projects`、`GET /api/v1/projects/{projectNo}` 匿名可读，展示目标/已筹/已支出/进度/剩余天数/预算/已入账流水 |

金额一律按**分**存储和传输，例如 3000 元 = `300000`。

## 2 接口

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| `POST` | `/api/v1/projects` | 动物管理员 | 创建项目；`submit` 省略默认 false，返回草稿 |
| `GET` | `/api/v1/projects` | 匿名 / 登录 | 公开列表；`status` 可逗号多选，`targetType`、`keyword`、`page`、`size` 可选 |
| `GET` | `/api/v1/projects/{projectNo}` | 匿名 / 登录 | 公开详情；管理端登录后可见草稿/待审核/驳回 |
| `PUT` | `/api/v1/projects/{projectNo}` | 动物管理员 | 修改草稿或驳回项目；`submit=true` 时提交审核 |
| `PUT` | `/api/v1/projects/{projectNo}/audit` | 动物管理员 | `decision=APPROVE/REJECT`；驳回必须带 `reason` |

### 2.1 创建请求

```json
{
  "name": "冬季流浪猫医疗基金",
  "purpose": "用于校园流浪猫绝育与伤病治疗，费用凭票据入账。",
  "targetType": "ANIMAL",
  "targetAmount": 300000,
  "startDate": "2026-11-21",
  "endDate": "2026-12-31",
  "budget": [
    {"subject": "检查", "amount": 120000, "note": "血常规与影像"},
    {"subject": "药品", "amount": 180000}
  ],
  "submit": true
}
```

约束：

- `name` <= 64 字，`purpose` <= 2000 字且必填；
- `targetType` 只能是 `ANIMAL / GROUP / MIXED`；
- `targetAmount > 0`，预算至少 1 项、最多 50 项；单项科目 <= 32 字、金额 > 0、备注 <= 255 字；
- `startDate/endDate` 必填，`endDate >= startDate`；
- 预算合计 > 目标金额：`40101`，`data` 为 `{targetAmount, budgetTotal, excessAmount}`；
- 编号格式 `PRJ-年份-流水`（至少三位，按年重新计数），由 `seq_no` 发号。

### 2.2 状态机

```text
DRAFT --SUBMIT--> PENDING_AUDIT --APPROVE--> FUNDING
REJECTED --RESUBMIT--> PENDING_AUDIT --REJECT--> REJECTED
FUNDING --> PENDING_SETTLE --> SETTLED --> ENDED
```

`PUT /projects/{no}/audit` 只接受 `PENDING_AUDIT`；其他状态返回 `40108`。项目审核只允许 `ANIMAL_ADMIN`，`SYSTEM_ADMIN` 不具备业务审核权。

## 3 公开可见性

公开列表/详情只展示以下状态：

`FUNDING`、`PENDING_SETTLE`、`SETTLED`、`ENDED`

`DRAFT / PENDING_AUDIT / REJECTED` 对匿名用户返回 `30410`，避免草稿与驳回理由泄露。动物管理员登录后可查看全部状态；系统管理员按普通公开口径读取。

项目路径同时注册在可选鉴权拦截器下（允许匿名 GET）。写接口在控制器内再次显式校验 `ANIMAL_ADMIN`，避免可选鉴权路径绕过 `@RequireRoles`。

## 4 进度口径

- `progressPercent = min(100, floor(raisedAmount * 100 / targetAmount))`；
- `daysRemaining = max(0, endDate - 今天)`，时区 `Asia/Shanghai`；
- `donationCount` 只统计 `donation.status='VERIFIED'` 的已入账笔数；
- `budgetTotal` 为预算明细合计；
- 公开详情返回最近 10 条已入账流水，字段仅 `donationNo / donorDisplay / amount / message / verifiedAt`，不含用户 ID、手机号或凭证地址；
- `raisedAmount / spentAmount` 读取项目冗余汇总；`raisedAmount` 已由 T3.1 核对入账维护，`spentAmount` 待 T3.3 复核后维护。

## 6 后续边界

- 捐赠登记与核对入账已在 T3.1 实现，登记不改进度、核对 `VERIFIED` 后才递增 `raisedAmount`。
- T3.2/T3.3 才实现支出登记、行锁余额与双人复核；本轮 `spentAmount` 只展示既有值。
- 项目结项、公示、台账与导出属于 T3.4/T3.5，本轮不实现。
- 项目编辑接口复用创建请求体；仅修改时也必须重发完整字段，`submit=true` 才进入待审核。
- 现有 `state-machine` 的 `FUNDING -> PENDING_SETTLE -> SETTLED -> ENDED` 已定义，结项前置校验留给 T3.4。
