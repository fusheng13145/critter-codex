# T1.4 健康与防疫记录实现说明

> 覆盖 `03 §6.2 #9—#10` 与 `02 FR-A-05`。只做个体健康记录，不写群体、不写消息表；提醒以接口字段形式提供给前端，消息投递留给 C。

## 1 已实现接口

| 方法 | 路径 | 权限口径 | 行为 |
|---|---|---|---|
| GET | `/api/v1/animals/{code}/health` | 登录可见 | 按记录时间倒序返回疫苗、驱虫、体重、病史；带 `reminderDue` / `daysUntilNext` |
| POST | `/api/v1/animals/{code}/health` | 管理员 | 新增记录，返回 `healthRecordId` |

记录字段：`type`（VACCINE / DEWORM / WEIGHT / HISTORY）、`recordedAt`（带时区）、`result`、`nextDate`（可选）。

## 2 校验规则

| 规则 | 错误码 |
|---|---|
| 类型为空、记录时间为空、结果为空或超过 255 字 | 30301 |
| 类型不在枚举内 | 30303 |
| 记录日期早于建档日 | 30301 |
| `nextDate` 早于记录日期 | 30301 |
| 编号不存在 | 30410（HTTP 404） |

`recordedAt` 统一换算到 `Asia/Shanghai` 后落库，避免跨时区把日期算错一天。

## 3 提醒口径

- 只对 `VACCINE` 且填写了 `nextDate` 的记录计算提醒。
- `daysUntilNext = nextDate − 今天`；`daysUntilNext ≤ 3` 时 `reminderDue = true`，包含已逾期。
- 非疫苗记录即使有 `nextDate` 也不提醒；体重、病史通常不带计划日期。
- 提醒是查询时计算，不落冗余表，也不会因定时任务漏跑而丢提醒。

## 4 分层落点

| 层 | 文件 |
|---|---|
| Controller | `controller/archive/HealthController.java`、`CreateHealthRecordRequest.java` |
| Service | `service/archive/HealthService.java` + `AddHealthRecordCommand`、`CreatedHealthRecord`、`HealthRecordView` |
| Domain / Mapper | `domain/model/HealthRecord.java`、`mapper/HealthRecordMapper.java` |

`type` 在请求体里先按字符串接收再解析，保证非法枚举返回 30303，而不是被 Jackson 的 `HttpMessageNotReadableException` 吞成 50001。

## 5 已知缺口

| 项 | 现状 | 处理 |
|---|---|---|
| 消息投递 | 只回提醒字段 | 等 C 的消息通道；B 不直接写 `message` 表 |
| 鉴权 | `X-User-Id` 占位 | 等 A 的令牌与角色落地 |
| 全量待办 | 只能按动物查 | 若要做管理端“今日疫苗待办”，需另定只读接口，避免擅自扩展契约 |
| 体重结构化 | `result` 存字符串 | 一期够用；如需算生长曲线，再加数值字段与单位 |
