## 逐字讲稿

### 0:00–0:25 开场

各位评委老师好，我是成员 B，负责档案与资金这条主线。我们做的是“青檐万灵册”校园生物档案与救助平台。它要解决三个具体问题：校园动物档案分散、救助过程不可追踪、募捐资金不透明。

### 0:25–0:55 架构

技术栈是 Vue 3 + Element Plus 前端，Spring Boot 3.5 + MyBatis-Plus + MySQL 后端，Flyway 管理数据库版本。后端按档案、救助、资金、认养、医疗五个域拆分，统一响应体、统一异常码、统一审计日志；关键写操作都有事务边界和状态机约束，不是把业务逻辑堆在 Controller 里。

### 0:55–2:35 业务走查

**第一步，档案。** 打开动物档案，当前有 200 条真实演示数据。筛选“治疗中”，可以看到团子这类个体的品种、毛色、发现点位、健康记录和状态时间线。状态变更不是随便改字段，而是走状态机，非法迁移会被拒绝。

**第二步，救助。** 打开工单看板，60 条工单覆盖待处理、处理中、待回访、已关闭和超时。点开一条超时工单，可以看到来源上报、处理时限和完整时间线。工单超时由定时任务扫描，条件更新保证多实例只写一次审计。

**第三步，资金。** 回到募捐项目，公开列表有 10 个项目，因为草稿和待审核会被过滤。打开 `PRJ-2026-009`，已筹 4,284,624 分、已支出 170,000 分，台账 93 笔。收入只认已核对捐赠，支出只认已通过复核，待核对和待复核都不入账，所以页面上的余额和逐笔流水能对上。

**第四步，支出复核。** 45 条支出覆盖一签、二签、待复核和驳回。大额支出超过 500 元必须两个人复核，登记人不能复核自己；第二签通过才更新项目已支出。这条规则有专门的事务用例，自复核会被 `40104` 拦截，且不产生任何资金副作用。

**第五步，结项公示。** 项目结项后生成公示，包含收支汇总、结余去向和报告。这个页面不需要登录，评委老师现在就可以直接用这个链接打开；后端匿名只读，前端路由也放行，分享给捐赠人不会跳登录页。

### 2:35–3:15 工程与数据

演示数据不是手工灌的，而是固定种子生成器加可重复执行 SQL：200 档案、12 项目、1200 捐赠、5 群体，另有 45 条支出、60 条工单、160 条健康记录。导入后自动核对 `raised_amount` 和 `spent_amount`，当前差异为 0。

并发方面补了 6 条真实 MySQL 用例：并发建档取号、同动物认养审核、同笔捐赠核对、同笔支出复核、到期扫描多实例、自复核拦截，全部通过。过程中发现发号器“先 INSERT IGNORE 再 SELECT FOR UPDATE”会死锁，已改成单条原子 upsert，这个问题不是压测出来的，是并发用例真实复现后修掉的。

部署方面提供 Compose、Nginx 反代、MySQL 备份与恢复脚本；备份已做恢复演练，恢复到演练库后四张核心表仍是 200 / 12 / 1200 / 5。

### 3:15–3:50 收尾

最后总结：这套系统不是只有页面，而是把“发现—上报—受理—治疗—募捐—支出—结项”做成了可执行、可审计、可复现的闭环。后续我们会补校园真实底图、移动端适配和更多物种识别能力。我的汇报到这里，谢谢各位老师。

## 评委可能追问

| 问题 | 回答要点 |
|---|---|
| 为什么不用微服务？ | 课程项目团队规模小，模块化单体 + 明确域边界足够；事务和部署成本更低，后续可按域拆 |
| 并发安全靠什么？ | 数据库行锁/条件更新 + 唯一索引 + 状态机；发号器原子 upsert；用例覆盖重复入账与重复迁移 |
| 捐赠和支出如何对账？ | 只统计 `VERIFIED` 捐赠与 `APPROVED` 支出，金额单位统一为分，台账按时间合并，导入后做恒等式校验 |
| 大额支出双签怎么防绕过？ | 登记人不得复核；第一签与第二签必须是不同管理员；仅第二签落 `APPROVED` 并更新项目已支出 |
| 匿名公示会不会泄露隐私？ | 仅返回结项报告、收支汇总和公示字段；不返回捐赠人、联系方式、内部工单 |
| 数据能不能复现？ | 固定种子生成器 + `qywl-demo.sql` + `reset-demo.ps1`，一条命令重置并输出数量与资金差异 |
