# T1.3 动物状态迁移说明

> 状态：已完成（2026-11-21）。状态迁移从普通字段编辑中拆出，走表驱动状态机并写 `animal_status_log`；无新增数据库迁移（表与字段随 V1 建库）。

## 1 设计取舍

| 项 | 做法 | 原因 |
|---|---|---|
| 状态字段 | `PUT /animals/{code}/status` 独立接口 | 状态不能与毛色、备注等普通字段一起改，避免一次编辑绕过状态机 |
| 入参 | 只传目标状态 + 原因，不传事件 | 前端不需要知道 `REPORT_ACCEPTED` 等事件名；服务端从迁移表反查事件并 `fire` |
| 迁移日志 | 每次迁移写 `animal_status_log` | 记录 from/to/event/reason/operator/occurredAt，支持时间线追溯 |
| 允许集合 | 详情返回 `allowedStatuses` | 前端按钮只显示当前状态真正可达的目标，非法迁移仍由后端兜底 |
| 权限 | 仅 `ANIMAL_ADMIN` | 系统管理员可看档案，但不做业务状态判断 |

## 2 接口

### 2.1 迁移

```http
PUT /api/v1/animals/CAT-2026-001/status
Authorization: Bearer <ANIMAL_ADMIN token>
```

```json
{ "targetStatus": "TREATING", "reason": "学生上报受伤，已送医检查" }
```

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "code": "CAT-2026-001",
    "status": "TREATING",
    "allowedStatuses": ["ON_CAMPUS", "ADOPTED", "MISSING", "DECEASED"],
    "occurredAt": "2026-11-21T19:30:00+08:00"
  }
}
```

约束：

- `reason` 去空格后至少 5 字，否则 `30401`；
- 目标不在当前状态的允许集合内，返回 `30402`，`data` 含 `current / target / allowed`；
- `RELEASE`（放归）要求健康记录中存在 `HISTORY` 类型且结果包含“绝育”或“TNR”的记录，否则 `30603`；
- 迁移成功后同步更新 `status_changed_at`；目标为 `ADOPTED` 时 `adopted=true`，其他状态为 `false`。

### 2.2 历史

```http
GET /api/v1/animals/CAT-2026-001/status-history
```

返回按发生时间倒序的数组：

```json
[
  {
    "fromStatus": "ON_CAMPUS",
    "fromLabel": "在校园活动",
    "toStatus": "TREATING",
    "toLabel": "治疗中",
    "event": "REPORT_ACCEPTED",
    "eventLabel": "上报受理",
    "reason": "学生上报受伤，已送医检查",
    "occurredAt": "2026-11-21T19:30:00+08:00"
  }
]
```

### 2.3 详情

`GET /api/v1/animals/{code}` 新增/恢复：

- `allowedStatuses`：当前状态可达的目标列表，供前端渲染按钮；
- `internalNote`：仅管理员下发，公开详情不返回。

## 3 前端

- `AnimalStatusDialog.vue`：目标状态下拉只取 `allowedStatuses`，原因必填 ≥5 字，提交后回显新状态与允许集合；
- `AnimalDetailView.vue`：状态按钮、状态时间线；按钮与时间线均只对 `ANIMAL_ADMIN` 可见，与后端权限一致；
- 时间线展示 `fromLabel → toLabel`、事件标签、原因、发生时间；无记录时显示空态，不伪造。
