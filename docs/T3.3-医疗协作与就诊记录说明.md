# T3.3 医疗协作与就诊记录说明

> 范围：成员 C 的 M09 医疗协作——合作医院列表与新增、管理员登记/纠错就诊、按就诊编号查询详情、按档案编号反查就诊。`POST /clinics` 与 `PUT /visits/{no}` 已在本轮补齐。

## 1 接口

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/v1/clinics` | 登录 | 返回合作医院、联系人、电话、地址与示例报价 |
| POST | `/api/v1/clinics` | 管理员 | 新增合作医院，返回自增 `clinicId` |
| POST | `/api/v1/visits` | 管理员 | 登记就诊，返回 `visitNo` 等摘要 |
| PUT | `/api/v1/visits/{no}` | 管理员 | 纠错主诉、诊断、处置、费用与影像，原因写审计日志 |
| GET | `/api/v1/visits/{no}` | 登录 | 返回诊断、处置、费用、影像编号与来源备注 |

管理员角色：`ANIMAL_ADMIN`、`SYS_ADMIN`、`SYSTEM_ADMIN`。普通认养人调用新增医院、登记或纠错接口返回 20003；未登录返回 20001；记录不存在返回 30410。

## 2 就诊编号

`visit_no` 格式定为：

```text
VS + 到院日期 yyyyMMdd + 3 位年度序号
```

示例：`VS20261120001`。序号复用 `seq_no`，按业务类型 `VISIT` 与到院年份递增。该格式此前未在已核对文档中固定，本实现作为当前团队口径；若后续接口文档发布不同前缀，需要统一迁移或重发号。

## 3 数据库

`visit` 表在 V1 已有医院、动物、工单、时间、主诉、诊断、处置、费用与 `file_ids`。V15 新增：

```sql
ALTER TABLE visit
    ADD COLUMN source_note VARCHAR(255) NULL COMMENT '无工单时的来源备注' AFTER file_ids;
```

原因：功能要求“无工单就诊须备注来源”，但原表没有独立字段。没有把来源塞进 `complaint`，避免主诉与来源语义混在一起。

## 4 业务规则

- `animalId`、`clinicId`、`visitedAt`、`cost` 必填；`cost` 为整数分且不小于 0。
- `visitedAt` 不接受晚于当前时间；按服务器时钟与 `Asia/Shanghai` 落到 `DATETIME`。
- 无 `orderId` 时 `sourceNote` 必填；有 `orderId` 时可空。
- 有 `orderId` 时必须存在，且工单 `animal_id` 与就诊动物一致，否则 30301。
- 主诉、诊断、处置、来源备注最长 255 字符；影像编号不允许空字符串。
- `file_ids` 以 JSON 数组写入；查询时反序列化为 `fileIds`。影像本身仍受附件审核与授权约束，本接口只记录编号。
- 新增医院时 `clinicName` trim 后 1–64 字；`contact`、`phone` 各 ≤32 字，`address`、`priceNote` 各 ≤255 字；空白可选字段落库为 `NULL`。写入 0 行返回 50002，成功写 `CLINIC_CREATE` 审计。
- 纠错就诊只改 `complaint`、`diagnosis`、`treatment`、`cost`、`file_ids`；动物、医院、到院时间与 `source_note` 不变。`reason` 必填且 ≤255 字，不落 `visit` 表。记录不存在返回 30410，未填原因返回 30401，字段非法返回 30301，更新 0 行返回 50002。
- 纠错成功写 `sys_log`：`action=VISIT_CORRECT`、`biz_type=VISIT`、`biz_id=visitNo`，`before_json` 保存修改前详情，`after_json` 保存纠错原因与修改后详情。

## 5 前端

- `/medical` 由 `MedicalView.vue` 接管，替换原占位页。
- 登录用户均可查看合作医院与按编号查询；只有管理员看到“登记就诊”“新增医院”和“纠错记录”。
- 新增医院在合作医院卡片内打开弹窗，保存后刷新列表；报价仍提示为课程示例。
- 就诊详情抽屉内提供“纠错记录”，只开放可编辑字段，纠错原因必填；保存后详情立即刷新。
- 登记表单以档案 ID 关联动物。成员 B 的档案页仍是占位页，因此暂不提供动物选择器；后续可改为按档案编号解析。
- 费用以元输入、提交时换算为分；影像编号用逗号分隔。
- 登记成功后自动按新编号查询并打开详情抽屉；也可手工输入 `VS...` 编号查询。
- 医院报价明确标注为课程示例，不构成真实价格承诺。
- 档案详情 `AnimalDetailView.vue` 新增“就诊记录”面板，调用 `GET /visits?animalCode=...` 反查该个体全部就诊，按到院时间倒序展示诊断、处置与费用。

## 7 档案反查扩展

`GET /api/v1/visits?animalCode=...` 是 35 接口之外的补偿查询，用于满足 FR-M-01 的“档案详情可反查就诊”：

- 登录可读，仍由 `/api/v1/**` 的 Bearer 鉴权保护。
- `animalCode` 必填；空白返回 30301，档案不存在返回 30410。
- 档案存在但没有就诊时返回空数组，不返回 30410。
- 返回结构为 `VisitDetail[]`，按 `visited_at DESC, visit_no DESC` 排序；字段与按编号查询一致。
- 前端只在档案详情内嵌该面板，不新增独立路由，也不改变 35 接口清单计数。

## 8 P1 追加：医院新增与就诊纠错

- `POST /clinics` 与 `PUT /visits/{no}` 已按第 6 节编号 43、46 补齐，不新增迁移，沿用 V1 的 `base_clinic` 与 `visit` 表。
- 报价口径：`priceNote` 仍是内部参考文本，接口不把它包装成公开承诺；前端继续标注“课程示例”。
- 纠错留痕：没有为 `visit` 增列“修改原因”，避免把审计信息混入业务表；原因与前后快照统一写 `sys_log`，满足“纠错留痕”，也不改变就诊详情对学生的展示字段。
- 并发边界：纠错按 `visit_no` 直接更新，未加 `version` 乐观锁。当前场景是管理员单人纠错，冲突概率低；若后续出现多人同时编辑，应补版本号并返回 50002。
- 医院删除：本轮不做。`visit` 对 `base_clinic` 有外键，直接删除会破坏历史就诊详情；若确需停用，后续应加 `enabled` 字段并只允许停用。
