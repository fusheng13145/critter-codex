# T3.1 捐赠登记与核对入账说明

> 状态：已完成（2026-11-21）。本轮无新增数据库迁移，沿用最新 main 的 V1→V12（本域不新增迁移）；`donation` 表结构不变，金额单位为分。

## 1 交付范围

T3.1 对应 FR-F-04、BR-07，覆盖：

| 能力 | 落地 |
|---|---|
| 捐赠登记 | `POST /api/v1/donations`，登录学生可提交，固定落 `PENDING_VERIFY` |
| 两态分离 | 登记不改 `project.raised_amount`；只有管理员核对为 `VERIFIED` 才入账 |
| 单笔核对 | `PUT /api/v1/donations/{donationNo}/confirm`，实收金额一致才入账 |
| 批量核对 | `PUT /api/v1/donations/batch`，请求 `{ "ids": [] }`，逐笔独立事务、部分成功不回滚 |
| 异常处理 | 实收金额与登记金额不一致时置 `ABNORMAL`，不写 `verified_at`，不动项目进度 |
| 管理员列表 | `GET /api/v1/donations`，按状态、项目筛选待核对/已入账/异常流水 |

`POST /donations` 原计划由 C 代写、B 验收；当前仓库没有实现，B 先落一版可联调的登记接口，后续 C 可按此契约替换或增强。`PUT /donations/{no}/flag`、`GET /donations/{no}/certificate` 不在 T3.1 范围。

## 2 两态与进度恒等式

```text
登记 create ──> PENDING_VERIFY ──核对金额一致──> VERIFIED ──> project.raised_amount += amount
                        │
                        └──核对金额不一致──> ABNORMAL（可再次核对）

VERIFIED 不可重复核对；ABNORMAL 允许人工再次核对。
```

- 登记：`status=PENDING_VERIFY`，`verified_at`、`verifier_id` 为空，`project.raised_amount` 不变。
- 入账：同一事务内锁 `donation` 行与 `project` 行，写 `status=VERIFIED / verifier_id / verified_at`，并把 `project.raised_amount` 加上本笔金额。
- 进度口径：`raised_amount` 必须等于该项目 `status='VERIFIED'` 的捐赠合计；核对前发现不相等返回 `40106`，拒绝把未入账金额计入进度。
- 公开进度读取 `project.raised_amount`；`v_project_fund` 按 `VERIFIED` 汇总，两者在同一事务内保持一致。
- 允许核对的项目状态：`FUNDING`、`PENDING_SETTLE`；`SETTLED/ENDED` 返回 `40108`。登记只允许 `FUNDING`。

## 3 接口

### 3.1 登记

```http
POST /api/v1/donations
Authorization: Bearer <token>
```

```json
{
  "projectNo": "PRJ-2026-007",
  "amount": 20000,
  "anonymous": true,
  "message": "给小猫加餐",
  "voucherFileIds": ["file-1", "file-2"]
}
```

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "donationNo": "DN202611210031",
    "status": "PENDING_VERIFY",
    "note": "登记已收到，待管理员核对到账后计入项目进度"
  }
}
```

约束：

- `amount` 1—10000000 分，非法返回 `40102`；
- `anonymous=true` 时 `user_id` 留空、展示名固定“爱心人士”；实名时展示昵称；
- `message` ≤100 字，`voucherFileIds` 至少 1 张、最多 10 张；
- 编号 `DN + yyyyMMdd + 当日流水`，至少四位，按天在 `seq_no` 单独计数。

### 3.2 管理员列表

```http
GET /api/v1/donations?status=PENDING_VERIFY,ABNORMAL&projectNo=PRJ-2026-007&page=1&size=20
```

返回 `PageResult<DonationSummary>`，行内包含 `donationNo / projectNo / projectName / donorDisplay / amount / anonymous / message / voucherFileIds / status / verifierId / verifiedAt / createdAt / updatedAt`。默认按 `updatedAt desc`。仅 `ANIMAL_ADMIN` 可读。

### 3.3 单笔核对

```http
PUT /api/v1/donations/DN202611210031/confirm
```

```json
{
  "amount": 20000,
  "paidAt": "2026-11-20T10:00:00+08:00",
  "voucherFileIds": ["file-proof"],
  "note": "财务到账"
}
```

- `amount` 省略时按登记金额核对；`paidAt` 只进 `sys_log` 审计，不覆盖 `verified_at`；
- 金额一致：返回 `status=VERIFIED`、`verifiedAt`、最新 `progress`（`raisedAmount/targetAmount/progressPercent`）；
- 金额不一致：返回 `status=ABNORMAL`、`verifiedAt=null`、进度不变，`note` 说明登记与实收差额；
- 已入账重复核对返回 `30301`；项目进度与流水不一致返回 `40106`。

### 3.4 批量核对

```http
PUT /api/v1/donations/batch
```

```json
{ "ids": ["DN202611210031", "DN202611210032"] }
```

```json
{
  "code": 0,
  "data": {
    "success": 1,
    "failed": [
      { "id": "DN202611210404", "code": 30410, "message": "捐赠记录不存在：DN202611210404" }
    ]
  }
}
```

- 单次最多 100 笔；按单号去重后逐笔核对；
- 每笔使用独立事务（`TransactionTemplate`），失败只记失败项，已成功笔不整体回滚；
- 批量只按登记金额核对，不把同一个 `amount` 套到多笔不同登记上；需要逐笔改实收金额时走单笔 `/confirm`；
- 路由取舍：接口清单写“`PUT /donations/{no}/confirm` 支持批量”，通用约定又要求 `PUT /xxx/batch`。本轮保留单笔 `/confirm`，同时新增 `PUT /donations/batch` 作为批量入口，两者语义不混用。

## 4 金额不符的落库方式

`donation` 表没有 `confirmed_amount` / `verify_note` 列，本轮不新增 V11：

- `donation.status` 置 `ABNORMAL`，`verifier_id` 记录核对人，`verified_at` 保持空；
- 登记金额保留在 `amount`，实收金额、实收时间与备注写入 `sys_log` 的 `after_json`；
- 再次核对时以新提交的实收金额重新判断，金额一致即可转 `VERIFIED` 并计入进度。

如果后续需要把“实收金额”做成可查询字段，再单独评估 V11 迁移；T3.1 不改变表结构。

## 5 测试与验收

| 层 | 用例 |
|---|---|
| 编号器 `DonationCodeGeneratorTest` | 2 例：`DN202611210031`、跨日新键 |
| 服务 `DonationServiceTest` | 10 例：匿名/实名登记、40102、非募集中 40108、入账递增进度、金额不符 ABNORMAL、重复核对、40106、项目状态拦截、批量部分成功 |
| 控制器 `DonationControllerTest` | 5 例：登记、列表筛选、单笔核对字段、40106 透传、批量结果 |
| 真库 `DonationIT` | 6 例：登记不改进度、入账同步 raised/视图/详情、金额异常、手工改进度 40106、批量 20 笔同步、批量部分成功 |

验收口径：

- 学生登记 200 元后，公开进度仍为 0；
- 管理员核对入账后，`project.raised_amount=20000` 分、公开进度 6%、`donationCount=1`；
- 同一项目批量核对 20 笔 10 元后，进度同步为 20000 分，`v_project_fund` 与 `project.raised_amount` 一致；
- 实收 150 元 / 登记 200 元时只转 `ABNORMAL`，进度不变。

## 6 后续边界

- T3.2 支出登记会在同一项目行锁下计算余额；T3.1 只增加 `raised_amount`，不改 `spent_amount`。
