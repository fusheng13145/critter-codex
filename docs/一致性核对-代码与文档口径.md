## 0 结论摘要

- 已核对**一致**的部分：错误码 45 条与 `03` §3 逐码对齐且无重复；四类状态枚举数量与 `04` 各 CHECK 值一致（动物 8 / 认养 7 / 项目 7 / 工单 5 / 群体 3）；分页 `page/size` 默认值与上限一致；业务编号三段式（`CAT-2026-001`）与 `03` §1 示例同构。
- 不一致共 **26 条**：P0 5 条、P1 8 条、P2 11 条、P3 2 条；另有**文档自身冲突 7 处**，是本次"口径不统一"的根因，须先修文档再动代码。
- 最需要先拍板的三件事：**技术栈与包根**（决定后续所有代码落位）、**非法迁移响应体**（决定 P02 页面与前后端契约）、**HTTP 状态码策略**（决定全局异常处理与前端拦截器）。

优先级定义：P0 = 影响架构或对外契约，越晚改成本越高；P1 = 行为与文档不符，影响功能正确性或联调；P2 = 契约缺口/测试失真，可在对应迭代补齐；P3 = 口径、风格与流程。
