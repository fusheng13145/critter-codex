# T3.7 志愿任务说明（成员 C｜D3 P1）

## 1. 范围

补齐接口 44–48：任务列表、发布任务、报名、到场打卡、我的任务。

- 后端：`volunteer/{controller,service,repository}`、`TaskMapper`
- 迁移：V19 `task` 增加标题/说明/服务时长，`volunteer.total_hours` 改为 DECIMAL
- 前端：`api/tasks.ts`、`views/volunteer/TaskBoardView.vue`，替换原 `/tasks` 占位页

## 2. 数据模型

`task` 在 V1 中已有编号、类型、点位、开始时间、名额、已报名、状态。V19 增加：

| 字段 | 说明 |
|---|---|
| `title` | 任务标题，1–64 字 |
| `description` | 补充说明，≤255 字 |
| `duration_hours` | 单次服务时长，0.5–12.0 小时 |

`volunteer.total_hours` 由整数改为 `DECIMAL(6,1)`，支持半小时粒度。`task_signup` 继续用 V1 的 `uk_signup_task_user(task_id,user_id)` 兜底重复报名。

## 3. 业务口径

| 动作 | 规则 |
|---|---|
| 任务编号 | `TASK + yyyyMMdd + 3 位年度序号`，复用 `seq_no` 的 `TASKyyyyMMdd` 键 |
| 发布 | 管理员；初始 `OPEN / joined=0`；写 `TASK_CREATE` |
| 报名 | 仅 `volunteer.status=ACTIVE`；任务行 `FOR UPDATE`；重复 30403；满额/非 OPEN 30402 |
| 满额 | 报名后 `joined >= quota` 置 `FULL`，之后报名 30402 |
| 打卡 | 必须已报名且未打卡；照片 fileId 必填；写入 `checkin_at/photo/hours` |
| 时长 | 打卡按任务 `duration_hours` 累加到 `volunteer.total_hours`，同一事务 |
| 我的任务 | `PENDING` 志愿者也可读，返回身份状态与总时长 |

## 4. 错误码

| 码 | 场景 |
|---|---|
| 20001 | 未登录 |
| 20003 | 非管理员发布；非志愿者报名/打卡；无志愿者记录 |
| 30301 | 标题/时长/名额/照片非法，开始时间缺失 |
| 30303 | 任务类型或状态枚举非法 |
| 30402 | 任务非 OPEN 或已满 |
| 30403 | 重复报名、重复打卡 |
| 30410 | 任务不存在、点位不存在、未报名打卡 |
| 50002 | 报名名额更新 0 行 |

## 5. 并发与事务

报名先 `SELECT ... FOR UPDATE` 锁 `task` 行，再检查名额与重复，随后写 `task_signup`、`joined+1`、必要时 `status=FULL`。数据库唯一键 `uk_signup_task_user` 兜底并发重复；`DuplicateKeyException` 转 30403。打卡更新条件带 `checkin_at IS NULL`，0 行按 30403，避免重复累计时长。

## 6. 前端

`/tasks` 页面包含“任务广场”和“我的任务”两个页签。管理员显示“发布任务”，活跃志愿者显示“报名”，已报名未打卡显示“到场打卡”（`PhotoUploader` 上传 fileId）。任务卡片展示类型、状态、时间、点位、名额与时长；我的任务展示累计时长与每条报名记录。

## 7. 边界

- 不提供志愿者申请/审核接口；本轮假设身份已由既有流程写入 `volunteer`，未审核用户报名返回 20003。
- 不提供任务编辑/取消/提前结束接口；清单只有 5 个接口。
- 打卡不校验经纬度或现场距离，只要求照片 fileId。
- `absent` 字段保留但本轮不提供缺勤标记入口。
