# T3.4 公告模块说明

## 范围

成员 C 负责的公告三接口，对应接口清单第 29–31 项：

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/v1/notices` | 公开 | 按分类分页，置顶优先 |
| POST | `/api/v1/notices` | 管理员 | 发布后立即生效 |
| GET | `/api/v1/notices/{id}` | 公开 | 正文与发布人 |

## 契约口径

- 分类英文码：`PROGRESS`（进展）、`PUBLICITY`（公示）、`SCIENCE`（科普）。
- 列表只返回 `published_at` 非空记录，排序 `pinned DESC, published_at DESC, id DESC`；空结果直接返回空页，不再查明细。
- 发布权限：`ANIMAL_ADMIN`、`SYS_ADMIN`、`SYSTEM_ADMIN`；`authorId` 只取 Bearer 上下文。
- 标题 trim 后 1–128 字，正文 trim 后 1–20000 字；字段非法 30301，分类非法 30303，写入 0 行 50002。
- 公告编号 `NT + yyyyMMdd + 3 位年度序号`，序号复用 `seq_no` 的 `NOTICE` 键，按年重置。
- 详情路径使用数字主键 `notice.id`；id 非法 30301、不存在或未发布 30410。
- 当前版本不提供删除/撤回接口，公示类公告因此在接口层没有删除入口。

## 实现位置

- 后端：`com.just.critter.notice`（controller / service / repository）、`NoticeMapper`、`NoticeEntity`、`NoticeRow`。
- 数据库：沿用 V1 `notice` 表，无新增迁移；`notice_no` 唯一键与 `idx_notice_publish(published_at,pinned)` 已满足查询。
- 鉴权：公告从 `OPTIONAL_AUTH` 移出，两个 GET 用 `@PublicEndpoint`，POST 用 `@RequireRoles`；避免可选鉴权拦截器跳过角色判定。
- 前端：`api/notices.ts`、`NoticeListView.vue`、`NoticeDetailView.vue`，路由 `/notices`、`/notices/:id`；消息中心提供公告入口，管理员在列表页发布。
