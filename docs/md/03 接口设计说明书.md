# 接口设计

> 本文是前后端唯一的通信契约。前端按本文写请求层与 Mock，后端按本文写 Controller 与 DTO，测试按本文写接口用例。路径、字段名、枚举值、错误码一经冻结（v1.0-frozen）只允许新增，不允许改名或删除；确需变更时在文末修订记录登记并同步双方。

## 1 技术约定

| 项目 | 约定 |
|---|---|
| 架构 | Spring Boot 3 + MyBatis-Plus + MySQL 8，前后端分离 |
| 风格 | RESTful，资源用名词复数，动作用 HTTP 方法表达；不可用方法表达的状态变更走子资源 + PUT |
| 基址 | `https://{host}/api/v1`，版本号进路径，破坏性变更升 v2 |
| 传输 | 全站 HTTPS；请求与响应均为 `application/json; charset=utf-8`；上传为 `multipart/form-data` |
| 鉴权 | JWT，`Authorization: Bearer {token}`，有效期 2 小时，刷新令牌 7 天 |
| 时间 | 一律 ISO-8601 带时区偏移，如 `2026-11-21T10:30:00+08:00`；日期用 `2026-11-21` |
| 金额 | 整数，单位"分"，字段以 `Amount` 结尾，如 `targetAmount: 300000` 表示 3000.00 元 |
| 编号 | 业务编号为字符串，如 `CAT-2026-031`、`AD20261121001`、`PRJ-2026-007`；数据库主键不外露 |
| 命名 | 路径 kebab-case，字段 lowerCamelCase，枚举 UPPER_SNAKE |
| 分页 | `page` 从 1 开始，`size` 默认 20、上限 100；排序 `sort=field,asc` |
| 幂等 | 写接口支持 `Idempotency-Key` 请求头，服务端缓存 10 分钟，重复请求返回首次结果 |
| 追踪 | 响应头回传 `X-Request-Id`，日志与错误提示均带该值，便于定位 |

## 2 统一响应体

所有接口（含错误）返回同一结构，前端只需处理一种壳。HTTP 状态码只表达传输层语义，业务结果一律看 `code`。

```
{
  "code": 0,
  "message": "ok",
  "data": { ... },
  "requestId": "b1f0c3d2-8a5e-4b77-9c11-2f4d6a8e9b03",
  "timestamp": "2026-11-21T10:30:00+08:00"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| code | int | 0 表示成功；非 0 见第 3 节错误码表 |
| message | string | 面向用户的中文提示，可直接展示；不含堆栈与技术细节 |
| data | object/array/null | 业务数据；失败时为 null，校验失败时为字段错误列表 |
| requestId | string | 链路追踪号，与日志对应 |
| timestamp | string | 服务端响应时间 |

分页数据固定包在 `data` 内的 `page` 结构里，前端分页组件可直接绑定：

```
{
  "code": 0, "message": "ok",
  "data": {
    "list": [ { "code": "CAT-2026-031", "name": "三花", "status": "TREATING" } ],
    "page": { "page": 1, "size": 20, "total": 137, "pages": 7 }
  }
}
```

校验失败时 `data` 返回字段级错误，前端可定位到具体输入框：

```
{ "code": 30301, "message": "参数校验失败",
  "data": [ { "field": "estimatedAge", "reason": "必须在 0—25 之间" } ] }
```

## 3 错误码

错误码按"业务族"分段，前两位标识族的范围，后三位为族内序号。前端可据此做统一处理：301xx 跳登录、302xx/303xx 提示表单、304xx—306xx 提示业务原因、401xx 提示资金规则。

| 码段 | 族 | 处理建议 |
|---|---|---|
| 0 | 成功 | — |
| 20001—20004 | 权限 | 跳登录或提示无权限 |
| 30101—30105 | 认证与账号 | 提示重新登录或账号状态 |
| 30201—30202 | 注册与学籍 | 表单提示 |
| 30301—30304 | 参数与输入 | 表单字段标红 |
| 30401—30412 | 档案与认养 | 弹窗说明原因 |
| 30501—30504 | 群体与物种 | 弹窗说明原因 |
| 30601—30603 | 医疗与工单 | 弹窗说明原因 |
| 40101—40107 | 资金 | 弹窗说明原因与差额 |
| 50001—50003 | 系统 | 提示稍后重试并给出 requestId |

## 4 鉴权与令牌

登录成功返回双令牌。访问令牌放内存（不落 localStorage，避免 XSS 窃取），刷新令牌存 httpOnly Cookie。前端请求拦截器在 401 且 code=30102 时静默刷新一次，仍失败则跳登录。

```
{
  "code": 0, "message": "ok",
  "data": {
    "accessToken": "eyJhbGciOiJIUzI1NiJ9...",
    "refreshToken": "eyJhbGciOiJIUzI1NiJ9...",
    "expiresIn": 7200,
    "user": {
      "id": "U202600173",
      "nickname": "青檐一号",
      "roles": ["STUDENT", "ADOPTER"],
      "primaryRole": "STUDENT",
      "menus": ["archive", "adopt", "report"]
    }
  }
}
```

访问令牌载荷只放必要声明，不放联系方式：

```
{ "sub": "U202600173", "roles": ["STUDENT","ADOPTER"],
  "scope": "animal:read adopt:write", "dept": "计算机学院",
  "iat": 1763692200, "exp": 1763699400, "jti": "9f2a..." }
```

权限判定分两层：接口层用 `@PreAuthorize("hasAuthority('expense:review')")` 拦截，服务层再按"角色-动作"白名单校验一次。这样即使注解配错，服务层仍能兜住；反之若只靠注解，改配置即可绕过，评审时站不住。

## 5 文件上传

上传分两步：先传文件拿 `fileId`，再把 `fileId` 挂到业务对象上。这样同一张照片可被多个对象引用（如就诊记录与支出票据共用一张发票照），也便于统一审核与去重。

```
POST /files
Content-Type: multipart/form-data
file: (binary)            // jpg/png/webp/pdf，≤5MB
bizType: EXPENSE_VOUCHER  // 业务类型，决定存储目录与审核策略
```

```
{ "code": 0, "message": "ok",
  "data": { "fileId": "F2026112100013", "url": "/api/v1/files/F2026112100013",
            "name": "发票.jpg", "size": 812341, "auditStatus": "PENDING" } }
```

校验规则：扩展名与 MIME 双校验；图片重编码去 EXIF（避免泄露拍摄位置）；文件名服务端重写为 UUID（防路径穿越）；`bizType` 为 `ANIMAL_PUBLIC` 的照片必须审核通过才在公开页出现。

## 8 通用约定补充

**排序与筛选。** 列表默认按 `updatedAt desc`；`sort` 只允许白名单字段，防止按未索引字段排序拖垮数据库。多值筛选用逗号分隔，空值表示不限。

**批量操作。** 批量核对、批量已读使用 `PUT /xxx/batch` 语义，请求体为 `{ "ids": [] }`，返回 `{ "success": n, "failed": [{ "id": "..", "code": 30410, "message": ".." }] }`。部分成功不整体回滚，前端展示逐条结果。

**并发控制。** 关键表带 `version` 字段，更新时校验版本，冲突返回 50002，前端提示"数据已被他人修改，请刷新后重试"。

**软删除。** 档案、项目、公告用 `deleted` 逻辑删除；资金流水禁止删除（40107），只允许冲正（新增一条负数记录并注明冲正对象）。

**导出。** 超过 5 万行走异步：立即返回 taskId，前端轮询 `/tasks/export/{taskId}` 取下载地址，避免请求超时。

## 9 前端对接约定

前端统包，最容易失控的不是页面多，而是每个页面各写一套请求。以下四条约定写进请求层，页面只调方法。

| 约定 | 实现 |
|---|---|
| 统一实例 | axios 单实例，`baseURL` 读环境变量，超时 15 秒，带 `X-Request-Id` |
| 拦截器 | 请求注入令牌；响应统一解包 `data`；`code !== 0` 抛业务异常；401 + 30102 静默刷新一次 |
| 错误展示 | 303xx 由表单组件消费字段错误；其余按 `code` 映射文案，兜底展示 `message` |
| Mock | 开关 `VITE_USE_MOCK`；每接口三套数据：正常、业务拒绝、空列表；Mock 文件与接口清单同名同序 |

接口层目录结构建议：`/web/src/api/{domain}/{resource}.js`，每个函数一接口一注释（路径 + 权限 + 对应功能点编号），便于事后对账。
