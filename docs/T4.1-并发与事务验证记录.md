## 本轮并发用例暴露的真实缺陷

### 1. 发号器首取死锁

原实现：

```sql
INSERT IGNORE INTO seq_no (biz_type, seq_year, current_no) VALUES (?, ?, 0);
SELECT current_no FROM seq_no WHERE biz_type = ? AND seq_year = ? FOR UPDATE;
UPDATE seq_no SET current_no = ? ...
```

并发首取时，`INSERT IGNORE` 的插入意向锁与重复键检查会和 `SELECT ... FOR UPDATE` 交叉，MySQL 抛出 `DeadlockLoserDataAccessException`；并发建档用例中多个事务被回滚。

修复：合并为单条原子 upsert，在同一行锁内完成建行、自增与会话值回写：

```sql
INSERT INTO seq_no (biz_type, seq_year, current_no)
VALUES (?, ?, LAST_INSERT_ID(1))
ON DUPLICATE KEY UPDATE current_no = LAST_INSERT_ID(current_no + 1);
SELECT LAST_INSERT_ID();
```

代码：`SequenceMapper.nextValue()` / `DatabaseSequencePort.next()`。

### 2. 项目到期任务角色越权

`StateMachines.project()` 的 `DEADLINE_REACHED` / `DEADLINE_MISSED` 迁移只允许 `ADMIN`，而 `ProjectDeadlineJob` 使用 `Role.SYSTEM`，5 个单测中 4 个抛 `StateTransitionException`。

修复：新增 `projectJob()` 迁移构造，仅两条到期事件使用 `ADMIN_OR_JOB`；其余项目迁移仍只允许管理员。

## 说明

- 用例类不加 `@Transactional`，否则子线程看不到未提交的测试数据；每个用例自行准备数据并在 `finally` 清理。
- 需真实 MySQL；H2 无法复现 InnoDB 行锁、死锁与 `LAST_INSERT_ID` 语义。
- 测试库由 `MySqlIntegrationTestSupport` 在类加载时重建，避免历史数据干扰。
