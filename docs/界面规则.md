# 界面规则：信息靠结构，不靠文字

这份规则约束全站界面。它的目的是让页面更好读（UX）、更好改（DX）、更好被后来的人或智能体接手（AX）。

---

## 1. 三类文字，只留第一类

| 类别 | 处理 | 例子 |
|---|---|---|
| **数据与状态**：编号、数量、金额、时间、状态名、后端返回的错误 | 保留 | `编号 CAT-2026-0031`、`已结案，待确认至 11-30` |
| **规则解释**：状态机怎么走、金额为什么双签、权限矩阵怎么配 | 删除 | "支出必须同时挂靠项目和动物" |
| **口号与装饰**：宣传语、主题名、小组分工、英文副标题 | 删除 | "让每一只校园生灵都被看见" |

判断标准：**删掉这句话，用户是否还能完成当前操作？** 能，就删。

## 2. 页面读不懂时改布局，不要加说明

按以下顺序解决，越靠前越好：

1. 字段名写清约束：`密码（8—32 位，含字母与数字）`，替代表单底部的提示条；
2. 表头承担单位与口径：`已筹（元）`，替代卡片右上角的"单位：元"；
3. 用分组与主次层级：把"待办"做成 `名称 + 数量 + 操作` 三列，替代一句话概括今天要做什么；
4. 用状态表达式：`待确认 · 剩余 3 天`，替代"逾期系统会自动确认"；
5. 用空态与骨架：加载用骨架条，空列表用空框，替代"正在读取数据…"与"暂无数据"文案。

只有一条例外：**失败信息**必须可读，因为它指向用户下一步要做什么。

## 3. 组件契约（由类型强制，不靠约定）

| 组件 | 只负责 | 明确不提供 |
|---|---|---|
| `PageHero` | 页面标题 + 右侧操作 | 说明文字入口（没有 `desc` 属性） |
| `PanelCard` | 卡片标题 + 右上控件 | 副标、口径注释（没有 `more` 属性） |
| `PageState` | 加载 / 失败 / 空三态 | 自定义加载与空态文案 |
| `MetricCard` | 指标名 + 数值 + 一行数据补充 | —— |
| `PhotoUploader` | 选图、上传、计数 | 提示文案（没有 `hint` 属性） |

属性被删掉这件事本身是有意的：写不进去，就不会再长回来。

## 4. 每次改动的三条验收

- **UX**：页面在零文案下仍能完成主流程；信息密度来自结构而不是句子。
- **DX**：改动集中在组件与样式令牌，页面不新增私有提示类；`npm run build` 通过。
- **AX**：命名与结构可被检索——状态、字段、组件各只有一种说法；不引入同义词与装饰性字段。

## 5. 换行与配置

仓库索引为 LF 换行。Windows 工作区保持 `core.autocrlf=false` 且工作树为 LF，避免整文件伪改动淹没真实 diff。
