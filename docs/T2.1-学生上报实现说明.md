# T2.1 学生上报实现说明

## 1 接口

| 项 | 内容 |
|---|---|
| 方法/路径 | `POST /api/v1/reports` |
| 鉴权 | 登录即可，不限制角色；匿名请求由 `AuthInterceptor` 拦住 |
| 操作人 | `AuthContext.require().id()`，不接收客户端 `X-User-Id` |
| 成功响应 | `{reportNo, status:"PENDING", deadline, duplicated, duplicateOf}` |

请求体：

| 字段 | 必填 | 规则 |
|---|---|---|
| `type` | 是 | `INJURED / NEW_ARRIVAL / ABANDONED / DISTURB / DEAD`，非法回 30303 |
| `pointId` | 是 | 必须存在于 `base_point`，不存在回 30410 |
| `photos` | 是 | 至少 1 个非空 fileId |
| `description` | 是 | 去空格后不少于 10 字 |
| `animalCode` | 否 | 传了就必须能查到档案，否则 30410；查到后落 `animal_id` |
| `contact` | 否 | 最多 64 字符，落库但不出现在公开响应 |

## 2 落库与编号

- 编号 `RP + yyyyMMdd + 当日流水（至少三位）`，流水在 `seq_no` 按天建行，跨日重新计数。
- `status` 创建即 `PENDING`；`deadline = 创建时间 + 24 小时`，时间截到秒，避免数据库 `DATETIME` 与响应纳秒不一致。
- `file_ids` 以 JSON 落库；`reporter_id`、`created_by` 均为当前登录用户。
- V6 新增 `report.animal_id`（FK `animal.id`，可空）与 `report.contact`（VARCHAR(64)，可空）。
  这样既满足 03 §7.5 的可选 `animalCode`/`contact`，也不需要把档案编号塞进描述文本；`contact` 只在后续管理员详情中使用。

## 3 24 小时去重

查询条件：同 `point_id`、`status <> CLOSED`、`created_at >= now - 24h`，取最早一条。

- 命中时仍插入新上报单，保证每条学生提交都有独立留痕；响应返回 `duplicated:true` 与 `duplicateOf:原单号`。
- 未命中时 `duplicated:false`、`duplicateOf:null`。
- 当前未加同点位并发锁，极端并发下可能两条都判为“无重复”；合并动作留给后续受理/关闭接口处理。

## 4 错误码

| 码 | 触发 |
|---|---|
| 30301 | 类型/点位/照片/描述/联系方式为空或长度不合规 |
| 30303 | `type` 不在五类枚举内 |
| 30410 | 点位不存在，或 `animalCode` 查不到档案 |

## 6 未覆盖与待拍板

1. **30503 野猪拦截尚未落地**：03 §7.5 的请求体没有 `speciesId`/物种字段，无法在服务端判断“物种为野猪”；当前只能由前端在选物种时先提示，或后续补可选 `speciesId` 后再接 30503。本轮不靠描述关键词硬猜，避免误拦。
2. **重复单策略**：本轮选择“仍插入新单并返回原单号”，保留每条学生提交；若后续确认应复用原单，只需改 `ReportService.create` 的插入分支与响应，不影响表结构。
3. **并发去重**：同点位并发提交未加锁，极端情况下会各自生成一单；受理/关闭接口落地时再按工单维度合并。
