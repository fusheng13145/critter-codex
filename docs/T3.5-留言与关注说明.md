# T3.5 留言与关注说明（成员 C｜D3 P1）

## 1. 范围

本轮补齐接口清单 35–39：发表留言、公开留言列表、管理员回复、关注、取消关注。实现位置：

- 后端：`interaction/{controller,service,repository}`、`mapper/InteractionMapper.java`、`V18__comment_status.sql`
- 前端：`api/interactions.ts`、`components/CommentPanel.vue`、`components/FollowButton.vue`
- 页面接入：`AnimalDetailView.vue`、`ProjectDetailView.vue`

## 2. 数据模型

`comment` 在 V1 中已存在，V18 增加 `status VARCHAR(20) NOT NULL DEFAULT 'VISIBLE'` 与 `idx_comment_status(status, created_at)`。状态只有 `VISIBLE / PENDING_AUDIT`，不做驳回状态机。

`follow` 沿用 V1：`uk_follow(user_id, biz_type, biz_id)` 保证重复关注不会产生多条关系；`user_id` 外键指向 `sys_user`。

## 3. 业务口径

| 动作 | 规则 |
|---|---|
| 目标校验 | `ANIMAL` 用档案编号；`PROJECT` 用项目编号 `projectNo`，兼容数字主键字符串 |
| 留言可见 | 匿名只看 `VISIBLE`；作者额外看自己的 `PENDING_AUDIT`；管理员看全部 |
| 敏感内容 | 命中引流/营销词写 `PENDING_AUDIT`，不直接公开 |
| 回复裁剪 | `replyContent` 只在公开回复、留言作者或管理员请求中下发 |
| 回复兼审核 | 回复 `PENDING_AUDIT` 留言即置 `VISIBLE`，并写 `COMMENT_REPLY` 审计 |
| 关注幂等 | 已存在关系直接返回，`newlyCreated=false` |
| 取消关注 | 只能删本人关系；0 行按 30410 处理 |

敏感词表当前内置在 `SensitiveWordFilter`，以“加微信 / 加qq / 代开发票 / 办证 / 博彩 / 刷单 / 贷款 / 返利 / 兼职日结 / http(s) / www.”为主，不写人身攻击词。后续应迁移到配置表，保持 `isSensitive` 接口不变。

## 4. 错误码

| 码 | 场景 |
|---|---|
| 20001 | 未登录发表留言、关注、取消关注 |
| 20003 | 非管理员调用回复接口 |
| 30301 | 内容为空或超长、`bizId` 为空、`visible` 缺失 |
| 30303 | `bizType` 不是 `ANIMAL / PROJECT` |
| 30410 | 动物/项目不存在、留言不存在、关注关系不存在或非本人 |
| 50002 | 留言/关注写入 0 行、回复更新 0 行 |

## 5. 前端行为

`CommentPanel` 嵌入档案详情与项目详情，支持分页读取、发表留言、管理员回复弹窗（含“仅留言者可见”开关）。`replyVisible=false` 的回复由服务端裁剪，前端不做“藏起来”的假隐藏。

`FollowButton` 在档案与项目页头展示。由于清单没有关注列表接口，无法在页面加载时回读关注状态；按钮只在本次会话内保存 `followId`，刷新后需要再次点击 POST 由幂等返回恢复。已在接口文档边界说明。

## 6. 边界与未纳入

- 无独立审核/驳回接口；回复待审留言视为通过，若需要严格审核状态机须新增接口。
- 无关注列表、无关注状态推送；FR-N-04 的“更新即推送”仍需消息生产接入。
- 留言与项目关联使用 `projectNo`，不使用数字主键，避免前端额外查询。
