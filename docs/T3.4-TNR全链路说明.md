# T3.4 TNR 全链路说明

> 范围：成员 C 的 P1 TNR 全链路——任务看板、发起抓捕、顺序推进转运/手术/放归/观察，末节点同步动物绝育标记。对应第 6 节编号 39–41。

## 1 接口

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/v1/tnr` | 登录 | 看板分页，支持 `stage`、`animalCode` 过滤，返回全节点时间线 |
| POST | `/api/v1/tnr` | 管理员 | 发起任务，首节点固定 `CATCH` |
| PUT | `/api/v1/tnr/{no}/node` | 管理员 | 只允许推进到当前节点的下一节点 |

管理员角色：`ANIMAL_ADMIN`、`SYS_ADMIN`、`SYSTEM_ADMIN`。普通用户可查看板，调用发起或推进返回 20003；未登录返回 20001。

## 2 阶段与编号

五节点固定顺序，不允许跳节点或回退：

```text
CATCH（抓捕）→ TRANSPORT（转运）→ SURGERY（手术）→ RELEASE（放归）→ OBSERVE（观察）
```

任务编号格式：

```text
TNR + 抓捕节点日期 yyyyMMdd + 3 位年度序号
```

示例：`TNR20261121007`。序号复用 `seq_no` 的 `TNR` 键，按节点发生年份递增。`OBSERVE` 即任务完成，不额外引入“已完成”状态；同一动物存在 `stage != OBSERVE` 的任务时不能重复发起。

## 3 数据库

`V1` 已有 `tnr_task`，保存当前节点快照。V16 新增 `tnr_node` 保存每次推进的责任人、时间、附件与备注：

```sql
CREATE TABLE IF NOT EXISTS tnr_node (
    id BIGINT NOT NULL AUTO_INCREMENT,
    tnr_no VARCHAR(24) NOT NULL,
    stage VARCHAR(16) NOT NULL,
    handler_id BIGINT NOT NULL,
    occurred_at DATETIME NOT NULL,
    file_ids JSON NULL,
    note VARCHAR(255) NULL,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    created_by BIGINT NULL,
    PRIMARY KEY (id),
    UNIQUE KEY uk_tnr_node_stage (tnr_no, stage),
    KEY idx_tnr_node_time (tnr_no, occurred_at),
    CONSTRAINT fk_tnr_node_task FOREIGN KEY (tnr_no) REFERENCES tnr_task (tnr_no),
    CONSTRAINT ck_tnr_node_stage CHECK (stage IN ('CATCH', 'TRANSPORT', 'SURGERY', 'RELEASE', 'OBSERVE'))
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4;
```

任务头保留 `stage / handler_id / occurred_at / file_ids / note` 的最近快照，节点流水承担历史追溯；唯一键 `(tnr_no, stage)` 从数据库层阻止同一节点重复写入。

## 4 业务规则

### 发起

- `animalId`、`occurredAt` 必填；`handlerId` 省略时取当前操作人。
- `occurredAt` 不得晚于当前时间，按服务端时区转为 `DATETIME`。
- `note` trim 后 ≤255 字，空白落 `NULL`；`fileIds` 元素不得为空白。
- 动物已有未完成任务返回 30403；动物或处理人不存在返回 30410；字段非法返回 30301。
- 写入任务头与首条 `CATCH` 节点，任一写入 0 行返回 50002。

### 推进

- `stage` 必须是当前节点的下一节点；跳节点、重复推进或已处于 `OBSERVE` 返回 30402。
- 推进到 `SURGERY` 必须至少一个 `fileIds`，否则返回 30601。
- `occurredAt` 必须严格晚于当前节点时间，否则返回 30301。
- 任务不存在返回 30410，阶段非法返回 30303，写入 0 行返回 50002。
- 目标为 `OBSERVE` 时更新 `animal.neutered=1`、`neutered_at=末节点日期`，不额外改动物状态；动物更新 0 行返回 50002 并整笔回滚。

## 5 前端

- 新增 `/tnr` 路由，菜单归属 `medical`，由 `TnrBoardView.vue` 接管。
- 看板展示任务编号、动物、当前节点、时间线进度、责任人与最近节点时间；点击编号打开详情抽屉。

## 7 边界

- `tnr_task` 只保留当前节点，历史必须查 `tnr_node`；不提供任务删除或回退。
- 同一动物只阻止“未完成任务”重复发起；`OBSERVE` 完成后允许再次发起，用于后续年度或再次救助。
- 观察节点即闭环，不引入额外随访状态；若后续需要持续观察，应新增阶段或独立随访表，不能复用 `OBSERVE`。
- 未做并发抢号保护：编号依赖 `seq_no` 原子递增，任务重复发起依赖 `hasOpenTask` 查询；高并发下仍需唯一约束兜底。
- 前端只完成构建校验，尚未做浏览器手工点验。
