# 联调环境说明（本地）

> 记录本机已就绪的数据库环境，供 B 自测与 A／C 联调时对照。口令不入库、不写进本文件。

## 1 实例

| 项 | 值 |
|---|---|
| 版本 | MySQL 8.4（Windows 服务名 `MySQL84`） |
| 地址 | `127.0.0.1:3306` |
| 字符集 | `utf8mb4` / `utf8mb4_0900_ai_ci` |
| 开发主库 | `critter_codex`，应用账号 `root`（本地开发用，口令由 B 持有） |
| 联调库 | `critter_codex_dev`，业务数据已导入演示集；Flyway 历史仍保留旧 V2/V14 记录，直接用最新后端连接前需 repair（见 §4） |
| 测试库 | `critter_codex_it`，仅真库 IT 使用；首个 IT 类加载时自动 DROP 重建，跑完不保留业务数据 |
| 只读账号 | `critter_ro@localhost`，仅 `SELECT`；口令由 B 单独发放，不写入仓库 |

连接串：

```
jdbc:mysql://127.0.0.1:3306/critter_codex_dev?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
```

## 4 注意事项

1. 只读账号只建在 `localhost`，队友从其他机器连不上；需要远程联调时再按需增加主机白名单，不要直接开 `%`。
2. Flyway 对 MySQL 8.4 给出 “latest supported version is 8.1” 警告，迁移实际成功；若要升级 Flyway，先单独跑 `MySqlSchemaIT` 与 `SeedReferenceDataIT` 再合。
3. 应用默认连 `critter_codex`（主库）；需要指向联调库时用启动参数覆盖，不在仓库里写死第二套账号：

```
--spring.datasource.url=jdbc:mysql://127.0.0.1:3306/critter_codex_dev?...
```

4. 医院报价、点位坐标均为示例/待校准数据，不能对外当作真实信息。
